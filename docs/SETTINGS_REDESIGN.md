# Упрощение раздела «Настройки» дашборда (frontend dash2)

Цель: всё редактирование сводится к трём формам в модальном окне: провайдер, профиль модели, роль. Одна форма служит и для создания, и для правки. Один режим вместо «простого» и «для специалиста».

## Что убираем
- «Какую модель спросить» (выбор модели при проверке подключения): проверка всегда идёт первой моделью провайдера.
- Блок «Для специалиста» целиком (профили, шаблоны, «Свой провайдер»), его строки «Короткое имя», «Файл ключа»: имя файла ключа берётся по id провайдера.
- Блок «Что подключено» со своей боковой панелью провайдера (ConnectBoard, ConnectPanel, ExpertBoard, ProviderAddForm, useProviderAdd, RolePanel, ProfileList): боковая панель роли и провайдера заменена модалкой. Боковая панель остаётся только для «Сколько стоит».
- Адрес страницы `?role=`, `?provider=` больше ничего не открывает; `?panel=swaps` и `?usage=` работают как раньше.

## Что сливаем
- «Что подключено» это список провайдеров: строка = название, включён ли, ключ, число моделей, лимиты словами, кнопка «Изменить». Биржи остаются отдельной маленькой строкой-списком (изменение биржи тоже в модалке).
- Лимиты расхода (деньги за день/час, токены за день, одновременные запросы) на сервере хранятся у провайдера (`llm.provider update patch.limits`), поэтому они внутри формы провайдера, в свёрнутом блоке «Ограничения расхода». Запросы в минуту (rpm) сервер не применяет, поле не показывается. В форме профиля лимиты провайдера показаны строкой «Расход ограничен: …» для справки.
- Особые параметры роли (свой дневной лимит денег, разброс, длина) переехали в форму роли, в «Дополнительно».

## Экран
Заголовок «Кто думает» (роли, как раньше для проверок) и далее списки: роли, профили моделей, провайдеры. В каждой строке кнопка «Изменить»; у профилей и провайдеров общая кнопка «Добавить» в заголовке списка. Ниже без изменений: «Сколько стоит», «Режим платформы», «Биржа».

## Три формы (UiModal: Esc, фокус-ловушка, aria-modal, возврат фокуса, fade + translateY 200 мс)
1. Провайдер (`llm.provider`). Новый: Название (id строится из названия сам), Тип (OpenAI-совместимый / Anthropic / DeepSeek), Адрес REST, флажок «Адрес во внутренней сети», Первая модель (обязательна для `add`). Кнопка «Создать» отправляет `add` (выключенным, без ключа), после успеха форма переключается в режим «изменить» этого же провайдера. Изменить: Название, Адрес (пусто = не менять), «Адрес во внутренней сети», «Ограничения расхода» (четыре поля; пусто = без потолка), кнопка «Сохранить» (одно `update` с patch из изменённого). Отдельные действия внутри формы: переключатель «Включён» (`enable/disable`), «Ключ» (механизм llmkey, значение сразу очищается; без расширенного управления подсказка `./tb llm key set ID`), «Получить список моделей» (`models`) с поиском, выбор или ручной ввод id и «Добавить» (`model_set`), «Проверить подключение» (`ping`, платный запрос назван).
2. Профиль (`brain.profile set`). Название (только при создании, id строится из названия), Провайдер, Модель, «Разброс ответов» (0..2), «Длина ответа» (токены), «Рассуждение» (по умолчанию / выключено / немного / средне / много). Значения по умолчанию: поля параметров пустые = «по умолчанию».
3. Роль (`brain.role chain`, для live-роли в live `brain.use`). Основной профиль, запасные (до четырёх, порядок, убрать, добавить), «Дополнительно»: дневной лимит денег и параметры ответа роли (`brain.role opts`, `opts_clear`). Одна кнопка «Применить».

## Безопасность и подтверждение рисков
Все записи идут через общий движок действий (`entities/action`): сервер решает, нужен ли challenge, единый диалог «Принимаю риски» (z-index выше модалки) показывается поверх; фразы и nonce возвращает интерфейс. Внутренняя сеть и смена адреса у провайдера с ключом дают предупреждения сервера (`accepted`). Ключ: поле type=password со случайным id, значение забирается и очищается при отправке, не попадает в адрес, стор и хранилище. Выключение провайдера live-роли и правки live-ролей в live по-прежнему отклоняет сервер, интерфейс предупреждает заранее. Бэкенд-контракт ctl не меняется.
