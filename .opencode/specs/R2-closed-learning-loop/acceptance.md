## Решения, принятые при реализации

- **Решение владельца 6 (2026-11-03, `5255f31`):** цикл и автопродвижение включены в поставке, без шага приёмки; безопасность держит код (прогрев, свежий сторож, аренда).

- **Порог предварительного замера мощности принят** без пересмотра (0.93 ≥ 0.5); повторный замер — после слияния R1.
- **CLI владельца в `tb.knowledge`** (`rulebook_cli`, `learn_cli`, `cli`), а не в `tb.learnloop.cli`: пакет цикла не пишет в `config/` и не импортирует CLI (`tests/test_layering.py`). Вместо `learnloop/sample.py` из дерева `design.md` выборка окна живёт в `learnloop/clusters.py`; продвижение вынесено в `learnloop/promote.py`.
- **`tb.knowledge.markers`** — отдельный модуль маркеров и классификатора `is_corruption` (без соединений), чтобы `labels.store` импортировал его без цикла импортов.
- **Сервис `learnloop` регистрируется писателем** и подтверждает чужой маркер восстановления, поэтому ручной `./tb knowledge restore` работает при запущенной платформе.
- **Сопровождение позиции (`fa718d0`)**: решение владельца по инциденту, вне спеки R2.

### Расхождения, найденные при документировании (задача 30)

1. **Назначение ролей при существующем `active.json`.** `swap._parse_target` принимает `shared.<роль>` только если роль уже есть в действующих назначениях; в `active.json`, созданном до задачи 27, `day_reviewer`/`retro` нет, поэтому `./tb brain role chain shared.day_reviewer ...` и дашборд отвечают «общая роль неизвестна». Единственный путь — `./tb brain reload --from-config`, который заменяет все цепочки содержимым `config/brain.json` (теряются назначения владельца других ролей). Требование 17.8 («профиль из настроек платформы как у любой роли») этим выполняется лишь частично. Нужна правка кода (добавление общей роли из конфига в действующие назначения новой ревизией), в документах описан обходной путь.
2. **Значения по умолчанию.** `config/brain.json` назначает ролям `ds-flash`/`ds-pro`, а Assumptions требований говорят, что профили берутся из настроек платформы без привязки; при отсутствии `active.json` и наличии ключа DeepSeek роли будут вызываться платно без явного решения владельца. Стоит решить: оставить или убрать роли из `shared_roles` поставки.
3. **Устаревший docstring** `src/tb/logic/learn_rules.py`, строка 232: «shadow_hits — вторая итерация»; `shadow_hits` реализован (`rulebook_view.shadow_hits`, `brain/cands.rule_check`). Поведение по спеке.
