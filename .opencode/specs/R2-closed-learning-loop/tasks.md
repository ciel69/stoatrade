# Implementation Plan: R2-closed-learning-loop

## Overview

Реализация блоков R2.0–R2.9 роадмапа в две итерации (деление и причины: `design.md`, «Объём первой итерации»; ревизии 2026-11-03: `design.md`, «Ревизии 2026-11-03»). Первая итерация (волны 0–12) замыкает цикл: диагноз, таблицы цикла и защита базы, снимки кластеров `cluster_runs` и воспроизводимые выборки окна (`cut_ts`), кандидаты кодом из недельного меню, проверка парным тестом на окне поиска и holdout фиксированной длины, уроки меток и сверка их статусов с базой, правила `skip_when`, испытание, продвижение с ожиданием на уровне правила, откат, вкладка «Память», блоки страницы «Учится ли мозг». Вторая итерация (волны 13–16): перенос случаев и уроков в SQLite с поиском по меткам, роли модели и порт заданий, недельная ретроспектива, размерные правила, справочные уроки мозга, заморозка продвижения, условие по нарушениям, `shadow_hits` и меню по сессиям.

Исполнители: субагенты по задачам; главный агент проверяет дифф, тесты и границы полномочий (Requirement 8). В ТЗ исполнителю фронтенда (задачи 19, 20) обязательно требовать навыков `impeccable` и `animate`. Код не пишется до утверждения спеки владельцем и команды начать реализацию (задача 3): все кодовые задачи, включая диагноз (задача 1), зависят от неё прямо или через цепочку. Вопросов к владельцу нет: четыре решения владельца и одобренные ревизии записаны в разделе «Решения владельца и автора» (правила во всех режимах включая live; полная автономность и автопродвижение без ручных шагов; только `skip_when`; модель из настроек платформы). Остальные решения принадлежат автору спеки и оспариваются владельцем в любой момент.

Каждая задача: критерии приёмки, тесты, зависимости строкой «Зависит от». Статусы по протоколу `kiro-specs` (`[ ]` → `[~]` → `[x]`).
